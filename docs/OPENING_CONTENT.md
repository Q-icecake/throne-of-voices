## 분류 범례와 검증 위험

- **A — 비교적 널리 인정되는 배경:** 이번 사료 대조가 없는 잠정 개요. 모든 항목에 ‘사람의 사료 대조 필요’를 표시했다.
- **B — 논쟁·불확실:** 사료 전승의 차이일 수 있는 문제와 이번에 확인하지 못한 세부 사항. ‘학계에서 논쟁 중’이라는 사실까지 검증한 것은 아니다.
- **C — 게임 재구성:** 접견·시간·문체·인물 표현·수치·결과의 창작 또는 시험 설정. 근거가 없는 내용을 역사 사실로 승격하지 않는다.

가장 위험한 다섯 묶음은 **① 연도와 사건 관계(A01/A02/B03), ② 호칭·관직·위치와 동석(A03/B05/C01), ③ 병력·지리와 관측 시점(B01/B03), ④ 조조 서신 전승과 창작 문구(B02/C03), ⑤ 인물의 내면·논리와 미래 결과(B04/C04/C05)**다. 사람은 판본·권차·쪽/항목·확인 문구·상충 자료·검토일을 기록하며 `historical-notes.md`의 체크박스를 확인해야 한다. 자료 후보의 제목을 기재했을 뿐 실제 사료 인용은 없다.

## M5 데이터 읽기 제안 — 확정 계약 아님

1. 서버에서 JSON을 읽고 독립 검사와 통합 시 추가할 schema 검사를 통과시킨다. 이 파일들을 브라우저 정적 자산으로 통째로 배포하지 않는다. M4 계약 확정 전에는 계약 파일을 수정하지 않는다.
2. ID는 콘텐츠 내부 참조다. 인물 ID는 현재 `player`, `zhang-hong`, `zhang-zhao`, `zhou-yu`, `lu-su` 표기를 따른다. D-/K-/L-/T/S 식별자를 기존 엔진 문서·지식·사건 ID와 연결하는 별도 매핑이 필요하다. 같은 이름이라고 런타임 타입이 같다고 보지 않는다.
3. 문서의 `body`는 현재 공개 문서의 `claim`에 대응시킬 후보이고, `source.author`·`evidence`·`regions`는 현재 평문 필드에 허용된 내용만 풀어 써야 한다. `observedAt.activeMs: null`은 미상이다. 현재 숫자형 시각 계약에 억지로 0을 넣지 말고 M4/M5에서 확정한 미상 표현에 맞춘다. `proposedArrivalActiveMs`는 실제 도착 기록이 아니다.
4. `readers`와 `eligibleReaders`는 허용 상한이다. 초기 보유·작성 완료·실제 수신·승인 공유를 기록해야 지식이 생긴다. 대사 선택에는 인물·태그·모든 `requiredKnowledgeIds`·접견/전달 가능 상태를 함께 검사한다. 플레이어가 읽었다고 NPC가 알게 하지 않는다. 현재 알지 못하는 지식의 요약을 Provider에 넘기지 않는다.
5. 사건의 자연어 조건을 코드처럼 평가하지 않는다. M4의 실제 상태를 참조하는 명시적 조건으로 옮기고 `events.md`의 취소·대체 규칙을 구현한다. T13은 엔진 진행의 투영이며 별도 비용·작업 실행기가 아니다. T14는 시작 이후 반응을 관찰하는 지표다.
6. 현재 조조 요청은 개시 때 이미 있다. T03은 같은 요청의 서신 도착이며, 이전 회신을 되돌리면 안 된다. T11은 **답변 완료 여부와 보류 기한을 발화 직전에 재검사**한다. 요청 생성 시점을 바꾸면 S06·S10도 함께 갱신해야 한다.
7. 테스트 JSON은 실행기 자체가 아니다. M4 접견·공유·회의 어댑터, M5 시계·사건 하네스, 필요하면 ScriptedProvider 응답 fixture를 추가해야 한다. 일반 한국어 대화는 현재 Mock이 처리하지 못한다. 모든 시험의 ‘Provider 필요’ 표시와 조작 단계의 현재 미구현 범위를 보존한다.

## 이번 단계의 결정과 기록

지식·사건 목록을 별도 JSON으로 더한 이유는 대사의 지식 경계와 시험의 사건 참조를 실제 검사하기 위해서다. 새 런타임 의존성을 추가하지 않았으며 `tests/`·`package.json`에는 검사기를 연결하지 않았다. 문서 본문은 189~212자, 대사는 모두 2문장이다. 정적 검사는 제한된 금지 표현 패턴을 찾을 뿐 모든 의미적 누출을 증명하지 않는다.

세부 작업 설명의 쓰기 허용 범위가 공통 규칙보다 좁으므로 `DEV_LOG.md`는 수정하지 않았다. 대신 `OPENING_VALIDATION.md`에 실제 결과와 미검증을 남겼다. 커밋은 작업 설명의 금지와 Git 메타데이터 읽기 전용 조건에 따라 시도하지 않았으며 리드에게 작업 트리 변경을 인계한다. 원본·main·다른 worktree·원격은 수정하지 않았다.
