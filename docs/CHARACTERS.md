# M4 인물 대화

## v0.2 NPC 입력·회의 정책 (023)

플레이어가 직접 쓴 **현재 입력은 현재 접견 참석자에게 하는 의도적인 공개**로 보아 Provider에 원문 그대로 보낸다. 따라서 비밀 작업 세부를 현재 문장에 직접 쓰면 그 내용도 전송된다. 이 원문을 다른 방의 현재 입력에 덧붙이지 않는다. 과거 대화·기억은 현재 참석자 전원이 목격한 것만 사용하며, 비밀 작업·전송 제외 표식은 담당자의 단독 접견에서도 외부 전송하지 않는다. 문서는 발언자·플레이어·현재 참석자 전원의 열람 권한과 전송 허용을 모두 요구한다. 비참석 인물의 기억·문서·발언을 현재 입력에 자동 삽입하지 않는다.

권한 필터 **다음에** 항목/JSON 문자 예산을 적용한다. 기억 12개/2400자, 최근 최대 6개를 다시 담는 요약 800자, 문서 6개/6000자, 지식 카드 4개/1200자, 최근 대화 최대 6개/2400자가 기본값이다. 최신 항목부터 완전한 항목 단위로 담고, 남은 예산에 안 맞는 항목은 건너뛴 뒤 원래 순서로 복원한다. 문서/기억의 문장을 잘라 사실의 뜻을 바꾸지 않는다. `NPC_MEMORY_ITEMS/CHARS`, `NPC_SUMMARY_CHARS`, `NPC_DOCUMENT_ITEMS/CHARS`, `NPC_CARD_ITEMS/CHARS`, `NPC_CONTEXT_CHARS`로 조절한다(각 기본값의 4배 이하 정수, 잘못된 값은 기본값; 0이면 해당 내용 제외). 문자 수는 UTF-16 JSON 길이이며 실제 토큰 상한을 뜻하지 않는다. 빈 배열/요약의 고정 포장 문자는 별도이다.

`NPC_MEETING_AI=1`을 서버 시작 전에 설정하면 질문/논의 회의에 **한 번의 Provider 호출로 주응답+반론 두 명만** 요청한다. 기본은 기존 주응답 AI+작성 반론이다. 세 번째 참석자는 듣기만 하며 그 사람의 비공개 지식은 넣지 않는다. 각 발언은 그 인물의 프로필, 공통 열람 근거, 고유 카드에 따라 작성한다. 기존 Proposal의 `dialogue` 문자열 안에 `{"speeches":[{"id":"zhang-zhao","text":"한국어 두 문장 이상","referencedKnowledgeIds":[]},…]}` JSON을 넣는 호환 옵션이며 외부 Proposal 참조 목록은 비운다. 어댑터/출력 schema를 바꾸지 않는다. 두 발언을 별도로 한국어·2~4문장·주응답 600자/반론 240자·존댓말 종결·허용 근거 ID·허위 완료 필터로 검사한다. 인물별 자연스러운 어조는 프로필 지시와 보수적 욕설/종결 검사로 보조하며 의미적 품질은 라이브 미검증이다.

잘못된 발언만 작성 대사로 대체하고 `speakers[].fallback`, `failureCode`, 기존 사건 기록/상태 칩/오류칸에 표시한다. 전체 호출 실패면 두 발언 모두 대체한다. 단독 대화 오류는 기존처럼 대화/초안을 변경하지 않는다. 보호 질문과 외부 전송 제외 근거를 다루는 로컬 응답도 작성 대사임을 표시한다. 항상 플레이어에게 발언권을 반환한다. 입력·초안은 오류 시 보존하고, Provider 보류는 `finally`에서 해제한다. 보존된 입력이 남아 있으면 작성 중 보류는 의도적으로 유지되며 지우거나 정상 재전송한 뒤 해제된다. 퇴실/공유/리셋/접견 전환 뒤 늦은 성공·실패는 상태/칩을 덮지 않는다.

`TalkResponse`의 선택 필드 `speakers`, `failureCode`, `usage`만 하위 호환 추가했다. `usage`는 전송한 JSON의 `inputChars/inputBytes`, 실제 공급자 계측의 `inputTokens/outputTokens/externalCalls`를 제공한다(모르면 `null`). 내용 없는 최근 50개 크기/계측 기록은 서버 로컬 `engine.npcUsage()`로 확인하고 리셋 시 비운다. 프롬프트나 비밀 원문을 usage에 기록하지 않는다.

작성된 대사 풀 기준 오프라인 구현, LLM 대사는 라이브 미검증. 인물의 역사적 성격을 단정하지 않는 게임적 재구성이다. 새 의존성, 외부 호출, 자동 사건 스케줄러는 없다.

서버 `server/characters.ts`에 정체성·입장·전문성·우려·카드와 초기 신뢰/존중을 둔다. 위치와 가용 상태는 `WorldState.characters`, 열람 권한은 문서의 `readers`가 기준이다. 초기 집무 기록은 장굉만 알고, 비공개 시험 수군 문서는 주유만 열람한다. 인물의 비공개 문서를 플레이어에게 자동 낭독하지 않도록 **발언자·플레이어·현재 참석자 모두 열람 가능한 문서만** 대화 입력에 포함한다. 따라서 주유의 서버 전용 시험 문서는 NPC 발언/Provider에도 들어가지 않는다. 실제 미공개 보고 전달은 후속 사건 경로에서 명시적으로 처리해야 한다.

## 호출과 명령 경계

- `POST /api/audience`: `{type:'invite', participants:[ID,…]}` (1~3명), `{type:'defer'|'dismiss', characterId:ID}`, `{type:'share', characterId:ID, documentId:ID}`.
- 초기 요청 목록은 장조→주유→노숙의 고정 시험 설정이다. ‘요청 순서대로 접견’은 첫 가용 요청자를 부른다. 연기는 기존 요청을 제거한 뒤 맨 뒤로 옮기며 UI에 순위를 표시한다. 모두 연기해도 현재 순서의 첫 가용 인물을 부른다. 별도 보류 상태는 없으며 직접 초대하면 요청 목록에서 빠진다. 이것은 M5의 자동 요청/스케줄러가 아니다.
- 초대는 서버에서 가용 상태/진행 중 임무를 검사한다. 접견자는 정무청으로, 퇴실자는 원래 위치로 표시한다. 이동 시간/자동 출발 이벤트는 M5 범위다. 첫 접견은 세션당 인물별 한 번만 기록한다.
- `POST /api/talk`: `{characterId:ID, text:'한국어 문장'}`. 현재 참석자만 발언할 수 있다. 응답은 `state`, `turns`, `inputOwner:'player'`, `source` 및 선택적 `outcome`/`notice`이다.
- M2의 Mock 해석기/검증기 또는 주입된 `InterpretationProvider` 파이프라인으로 질문·논의·명령을 구분한다. 명령은 기존 M3 초안 경로로 보내 실제 수행자(수군→주유, 유비→노숙 등)를 유지한다. 확인 전에는 실행하지 않는다. 알려진 금지·조건도 기존 검증을 그대로 거친다.
- 대화가 변경하는 것은 대화 원문·사건·기억과 그에 따른 리비전뿐이다. 자원·준비도·외교·작업·시간은 바꾸지 않는다. 문서 공유/접견은 별도 서버 행동이다. 공유를 반복해도 관계 변화나 공유 사건을 중복 생성하지 않는다.

## 지식·기억·관계

`characterInput()`은 명시적인 허용 목록으로 분리된 객체를 만든다. 전체 WorldState, 다른 인물의 입장/기억, 적의 실제 상태, 관계 수치는 포함하지 않는다. 발언자는 자기 카드와 참석했던 기록만 받고, 회의에서는 현재 참석자 모두 들었던 기록만 받는다. 개인적으로 공유받은 문서는 미공유 참석자가 있는 회의에서 인용하지 않는다. 이는 보수적인 공개 경계이며 자동 재공유 기능은 아니다.

문서 열람은 클라이언트 화면 전환이다. ‘보여 주기’만 서버 권한을 추가한다. 현재 접견 중인 인물과 플레이어가 열람 가능한 실제 문서 ID만 공유할 수 있다. UI에서 계산하는 장부(`ledger`)는 원본 문서가 아니므로 공유 버튼을 두지 않으며, 해당 작업의 보고 문서는 공유할 수 있다.

기억은 `{eventId, fact, witnesses}`와 서버 전용 근거 메타데이터(`taskId`/`documentId`/`providerExcluded`)를 저장한다. 최근 여섯 사실의 요약은 해당 event ID들을 그대로 참조한다. 질문·가정은 ‘플레이어가 질문·논의함’으로 저장하고 사실/실행으로 승격하지 않는다. 답변의 전체 원문은 사건/대화 기록에서 읽는다. 명령 확정 사실에는 실제 `command-confirm` ID와 금지 조건, ‘당시 아직 완료 아님’을 붙인다. 진행·완료·회수는 실제 후속 사건 ID로 추가하며 기억 답변은 최신 작업 기록을 우선한다. 출발 후 회수 미지원은 중단으로 바꾸지 않는다.

### R2a 전송 경계와 당사자 예외

열람 권한과 외부 Provider 자동 전송 권한은 다르다. `server/llm/context-policy.ts`의 공통 정책을 명령·대화 입력에 적용한다. 비밀 작업 보고, 작업에 연결된 확정/진행/회수 기억, 비밀 보고 공유 기억은 **장굉과 당사자 노숙을 포함한 모든 외부 Provider 입력에서 제외**한다. 요약은 필터를 통과한 기억으로 다시 만들며 서버 전용 메타데이터도 보내지 않는다. 비밀·모호 공개 범위의 과거 대화/명령도 자동 전송하지 않는다. 현재 플레이어가 직접 보낸 문장 자체는 해석 요청이다.

비밀 임무의 당사자는 해당 작업의 실제 담당자로 한정한다. 당사자만 있는 접견에서 문서·기억을 물으면 허용된 보고 또는 사건 기록 범위의 **로컬 답변**을 사용한다. 이 경로는 Provider를 호출하지 않으며 그 질문·답변을 이후 Provider 문맥/기억에 재첨부하지 않는다. 장굉의 전달자 권한이나 다른 인물에게 문서를 보여 준 행위는 이 예외를 확대하지 않는다. 혼합 회의에서는 해당 비밀 근거를 제외한다. 상대의 동맹 수락이나 참전은 기록에 없으면 덧붙이지 않는다.

문서 **공유 취소는 미지원**이다. 이미 알려진 정보와 공유 사건·관계 변화를 되돌리지 않는다. HTTP에 `unshare` 동작이 없으며 공유 취소가 된 것처럼 표시하지 않는다.

초기 신뢰/존중은 80/80인 내부 시험값이다. 새로운 문서 공유 시 존중을 최대 1 올리고 이유를 별도 관계 로그에 남긴다. 접견 연기·퇴실·의견 불일치로 신뢰를 떨어뜨리지 않는다. 숫자는 공개 응답/화면/Provider에 노출하지 않는다. Provider에는 정성적인 신뢰 관계만 전달하고, 관계 질문에는 실제 공유 사건을 기억하며 존중과 전문적 우려를 함께 표현한다.

## 대사와 회의

대사 풀은 고정 선택이며 난수 호출이 없어 같은 입력·지식 상태에서 결정적이다. 기본 답변은 2~4문장, 회의 반론은 2문장이다. 문서는 원문의 첫 문장 일부(최대 140자)를 인용하고 출처와 한계를 밝힌다. 미래·숨은 병력·적의 속마음·비공개 대화 질문은 한계를 밝히며, 해당 보호 패턴은 Provider 호출 전에도 적용한다. 일반 한국어 전반을 이해하는 모델이 아니며 이 유한 패턴의 포괄성은 보장하지 않는다.

회의는 지정한 한 사람이 답하고 다른 한 사람이 필요하면 짧게 반론한다. 세 명이어도 한 요청에 NPC 발언 최대 두 번이다. ‘둘이 논의해 봐’도 같은 한정된 교환이며 타이머나 자동 반복이 없다. 문서/기억/모르는 정보 답변에는 자동 반론을 붙이지 않는다. 인물 그림을 누르면 다음 질문의 발언자를 선택한다. 읽기·입력 중의 자동 힌트나 재촉은 없다.

Provider 교체 시 M2 인터페이스에 선택적 `character` 필드와 지식 카드 ID 참조를 제공한다. 원문 부정/조건/담당자 검증·타임아웃·오류 보존을 재사용한다. 접견 변경·공유·새 요청·리셋 뒤 늦은 응답은 버린다. 긴 모델 답변(600자 또는 4문장 초과)은 거절한다. 모델 주발언과 작성된 반론이 섞이면 `source:'mixed'`로 표시한다. 외부 호출은 이번 단계에서 **0회**이며 실제 한국어 품질·사전학습 미래정보 억제는 라이브 미검증이다.

명령 질문과 인물 대화는 같은 결과 주장 필터를 거친다. 모델의 출발·도착·수락·동맹·완료·전송·소모 및 비밀 사실 단정은 실행하지 않았다는 안내로 대체하며, `card-*` 등 내부 지식 식별자를 대사·기록에 넣지 않는다. 미래 계획·질문·가정 표현은 허용하지만 다른 절의 과거 사실 주장까지 허용하지 않는다. 이는 유한 한국어 패턴 방어이며 임의의 자연어 사실성 증명은 아니다. 엔진이 만든 보고·사건과 로컬 근거 답변은 별도다.

## 화면·검증

기존 S2에 대상 인물을 강조하고 S3에는 추가 참석자를 배치한다. 하단에 최근 발언, 기록 패널에 플레이어의 전체 대화를 둔다. 문서·지도·기록 전환은 입력을 유지한다. 임무 중 인물은 비활성 버튼과 사유를 함께 표시한다. 세 인물 SVG는 장굉 원본의 색·관·소품만 바꾼 **임시 표현이며 최종 아트가 아니다**.

검증: `tests/characters.test.ts` (지식·기억·공유·T06/T08·Provider 경계·명령·HTTP), `scripts/verify-m4.ts` (설치된 Edge, 1920×1080/1366×768, 네 접견·회의·공유·입력 보존·기록·임무 중 상태). 증거는 `artifacts/m4/`에 저장한다. 전체 기존 테스트/타입 검사/빌드와 M1/M2/M3/R1 브라우저 회귀도 실행한다. 자동 통과는 대사의 자연스러움이나 15분의 재미를 입증하지 않는다.

R2a 추가 검증: `tests/r2a-fixes.test.ts`, `node scripts/verify-m4.ts --out artifacts/r2a-fixes/characters`. 실제 talk Provider 입력, 악의적 대사, 지연 응답, 작업 기억, HTTP 길이/필드 경계, 연기 순서 및 3인 배치·세 발언자 전환을 검사한다. 수정 전 실패 기록과 두 해상도 스크린샷은 `artifacts/r2a-fixes/`에 둔다.
